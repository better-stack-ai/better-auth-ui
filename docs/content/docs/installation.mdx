---
title: Installation
description: Register Better Auth UI routes in a BTST application.
---

Use Node 22 or newer, React/React DOM 19.2.6 or newer, Tailwind 4.3.2 or newer,
TanStack Query 5.101.2 or newer, and a supported Better Auth cohort. New integrations
use Stack 5 with Better Auth 1.7.14 and matching API-key/passkey plugins:

```sh
pnpm add @btst/better-auth-ui@3.0.2 @btst/stack@5 @btst/yar@^1.3.2 better-auth@1.7.14 @better-auth/core@1.7.14 @better-auth/api-key@1.7.14 @better-auth/passkey@1.7.14 @better-auth/utils@0.5.1 @better-fetch/fetch@1.3.3 better-call@1.4.4 @tanstack/react-query@5.105.0 @tanstack/query-core@5.105.0
```

Keep `@tanstack/react-query` and `@tanstack/query-core` on the same resolved
version; the coordinated Stack 5 cohort uses 5.105.0 for both and includes BTST DB
3.0.1. Optional Better Auth plugins such as SSO, OAuth provider, and Stripe must
also match 1.7.14.

Existing Stack 4/Auth 1.7.6 consumers remain supported. Keep that Auth cohort
aligned, including API-key/passkey and any optional Auth plugins, when staying
on Stack 4.

Import the package's Tailwind source registration after your Tailwind import:

```css
@import "tailwindcss";
@import "@btst/better-auth-ui/css";
```

Keep BTST's usual shadcn theme variables. Components and primitive dependencies
ship with the package; you do not need to copy the upstream registry into each app.

The route factories are safe to call during SSR:

```tsx
import { createClientStack } from "@btst/stack/client"
import { authClientPlugin, accountClientPlugin, organizationClientPlugin, adminClientPlugin } from "@btst/better-auth-ui/client"

const stack = createClientStack({
  queryClient,
  api: { baseURL, basePath: "/api/data" },
  site: { baseURL, basePath: "/p" },
  plugins: {
    auth: authClientPlugin(),
    account: accountClientPlugin(),
    organization: organizationClientPlugin(),
    admin: adminClientPlugin()
  }
})
```

Configure browser customization in your existing StackProvider:

```tsx
import { StackProvider } from "@btst/stack/context"
import { organizationPlugin } from "@btst/better-auth-ui/plugins/organization"
import { adminPlugin } from "@btst/better-auth-ui/plugins/admin"

<StackProvider
  stack={stack}
  router={routerAdapter}
  overrides={{ auth: {
    authClient,
    redirectTo: "/p/account/account",
    socialProviders: ["github"],
    plugins: [organizationPlugin({ teams: true }), adminPlugin()],
    onSessionChange: () => router.refresh()
  } }}
>
  {children}
</StackProvider>
```

`authClient` is the application's native Better Auth client, configured with the
matching Better Auth client plugins. BTST's optional identity/authorization adapter
is independent: it is not needed by this UI and does not replace Better Auth's
sessions or permission checks.

The bridge takes navigation, links, notifications, translations, per-plugin site
endpoints, and the request's QueryClient from StackProvider. Place
`BetterAuthPluginProvider` around embedded components such as `UserButton` inside
StackProvider; routed pages already provide this bridge.

Same-origin pushes use the configured router. Since StackRouter has no replace
method, replacement navigation uses `window.location.replace`. Cross-origin
navigation always uses the browser. Upstream server helpers can prefetch sessions
into the request's shared QueryClient; never reuse a server QueryClient across users.
